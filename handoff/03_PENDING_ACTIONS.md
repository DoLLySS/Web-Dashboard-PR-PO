## ค้างหลัง S2b (ส่ง Master-List ผ่าน Flow: เขียนและทดสอบกับ Flow ปลอมแล้ว)

- ปลายทางและฟิลด์ Master-List เจ้าของเว็บยืนยันแล้ว (`/api/pr-po/ingest`, กันซ้ำด้วย `requestId` ด้วย unique index; ส่งซ้ำ requestId เดิมตอบ 200 ไม่สร้างแถวซ้ำ แต่ถ้าข้อมูลแก้แล้วเว็บไม่อัปเดตแถวเดิม ต้องใช้ requestId ใหม่และให้แอดมินปฏิเสธแถวเก่า) ส่วน Flow ส่งไฟล์ขึ้น SharePoint ยังรอ IT (`02_S0_IT_REQUEST.md`)
- **ปลายทาง Master-List ภายในที่เป็น http (ใช้ `MASTERLIST_ALLOW_HTTP=1`):** ตัวเลือกนี้มีไว้ทดสอบเท่านั้น (ค่าเริ่มต้นปิด รับ http เฉพาะ IP ภายใน 10.x / 172.16-31.x / 192.168.x และเฉพาะ `MASTERLIST_API_URL` ส่วน Flow ส่งไฟล์ขึ้น SharePoint ยังบังคับ https) ข้อมูลแถวและ `X-Api-Key` วิ่งแบบไม่เข้ารหัส **ก่อนใช้จริงต้องให้เจ้าของระบบเปิด https แล้วเปลี่ยน URL และปิดตัวเลือกนี้** และ**ต้องมีปลายทางทดสอบ** (หรือวิธีลบรายการทดสอบ) ก่อนยิงจากแอป เพราะทุกแถวที่บันทึกจะถูกส่งไปจริง ลองส่งด้วยข้อมูลปลอมแบบคำขอเดียวก่อนเปิดให้แอปส่งอัตโนมัติ
  - เจ้าของเว็บยืนยันปลายทางปัจจุบันเป็น `http://<IP ภายใน>:3000/api/pr-po/ingest` (http จึงต้องใช้ `MASTERLIST_ALLOW_HTTP=1`) ต้องให้เจ้าของระบบ/IT ตัดสินใจว่ายอมรับ http ในเครือข่ายภายในหรือไม่
  - ยังต้องถามเจ้าของเว็บ: ความยาว "max 300" นับเป็นอักขระ / byte / UTF-16, ขีดจำกัดของฟิลด์อื่น (tel, tax_id, qt_no, pr_run_no, category, sharepoint_url); และเว็บกัน PR เดียวกันที่ต่าง requestId (ต่างแถวใน DB) หรือไม่ (ตอนนี้กันซ้ำเฉพาะ requestId เดียวกัน)
  - ส่งแถวที่บันทึกแล้วซ้ำ: `venv/bin/python scripts/resend_masterlist.py --id <id>` (dry-run) แล้วใส่ `--send` เพื่อส่งจริง ส่งทีละแถว requestId คงที่ต่อแถว (uuid5 จากชื่อไฟล์ DB + id) รัน `--send` ซ้ำ id เดิมปลอดภัย แต่ถ้าข้อมูลแถวเปลี่ยนหลังส่งแล้วเว็บไม่อัปเดต ต้องใช้ requestId ใหม่และให้แอดมินปฏิเสธแถวเก่า อย่าส่งหลายแถว (หลาย id) ของ PR เดียวกัน
- ปุ่ม "ส่งแถวนี้เข้า Master-List ซ้ำ" และสถานะส่งแล้ว/ยังต่อแถว (ต้องแก้ schema) ทำหลังตัดสินใจเรื่อง `requestId`
- ทดสอบกับ Flow และปลายทางจริงด้วยข้อมูลปลอม/ไลบรารีว่างก่อน
