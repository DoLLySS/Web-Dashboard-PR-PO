# คำขอข้อมูล S0 — ส่งไฟล์เอกสารขึ้น SharePoint ผ่าน Power Automate

เขียนสำหรับ: IT / ผู้ดูแล Microsoft 365

## บริบท

ระบบ MasterList (Streamlit) เก็บไฟล์ PR/PO/ใบกำกับในเครื่อง ต้องการสำเนาออนไลน์บน SharePoint วิธีเดิมในโค้ดใช้ Client ID/Secret ผ่าน Azure ACS ซึ่ง Microsoft เลิกใช้กับ SharePoint Online ตั้งแต่ 2 เม.ย. 2026 ([MC693863](https://mc.merill.net/message/MC693863)) จึงเปลี่ยนเป็นให้แอปเรียก Flow ของ Power Automate (HTTP trigger) แล้ว Flow สร้างโฟลเดอร์และไฟล์ในไลบรารี

ฝั่งแอปเขียนเสร็จแล้วและทดสอบกับ Flow ปลอม **ยังไม่เคยคุยกับ Flow จริง** ไฟล์ในเครื่องยังเป็นต้นฉบับ ถ้าส่งออนไลน์ไม่สำเร็จ แถวและไฟล์ในเครื่องยังอยู่

## คำถามที่ต้องการคำตอบ

1. สิทธิ์ใช้ HTTP trigger ของ Power Automate (ปกติเป็นฟีเจอร์ Premium) บัญชี/ใบอนุญาตใดใช้ได้
2. Site URL, ชื่อ Document Library และโฟลเดอร์ราก พร้อม **ไลบรารีทดสอบที่ว่าง**
3. เจ้าของ Flow ควรเป็นบัญชีบริการหรือกลุ่ม ไม่ใช่บุคคล และ connection ต้องเขียนไลบรารีได้
4. นโยบายของ tenant ว่า HTTP trigger ให้ใครเรียกได้ (กรุณาตรวจกับเอกสาร Microsoft ปัจจุบัน)
5. เพดานขนาดคำขอและเวลาตอบของ Flow เทียบกับไฟล์ 50 MB (base64 ใหญ่ขึ้นราว 1/3) ถ้าไม่พอต้องแบ่งส่งเป็นชิ้น (ฝั่งแอปยังไม่รองรับ)
6. ต้องส่งข้อมูลแถวเข้า Master-List ด้วยหรือไม่ และเมื่อลบแถวต้องลบไฟล์ออนไลน์ด้วยหรือไม่ (ตอนนี้แอปไม่ลบไฟล์ออนไลน์) ถ้าต้องส่ง ขอคำตอบเพิ่ม (ดูหัวข้อ "สัญญาการส่งแถวเข้า Master-List" ด้านล่าง):
   - ปลายทางคืออะไร (SharePoint List / ไฟล์ Excel บน SharePoint / อื่น ๆ) และใช้ Flow ตัวที่ 2 หรือขยาย Flow เดิม
   - ฟิลด์ที่ต้องการครบตาม 13 ฟิลด์ที่เสนอหรือไม่
   - Flow จะใช้ `requestId` กันสร้างแถวซ้ำได้หรือไม่ (ข้อนี้ใช้ตัดสินใจเรื่องปุ่มส่งซ้ำด้วย)

## สัญญาการส่ง (ที่แอปทำตามอยู่แล้ว)

คำขอ: `POST` JSON ต่อ 1 ไฟล์
```json
{"requestId": "3f2b8c1e-5a7d-4c9e-8b21-0d6e4f7a9b13", "folderParts": ["2026","Mar","19","ชื่อโฟลเดอร์"], "fileName": "...", "contentBase64": "...", "sha256": "..."}
```
`requestId` คือ UUID ที่แอปสร้างต่อการส่ง 1 ไฟล์ และ **เท่ากันทุกครั้งที่แอป retry ไฟล์เดียวกัน** ขอให้ Flow จำ `requestId` ที่ทำสำเร็จแล้วและตอบลิงก์เดิมแทนการสร้างไฟล์ซ้ำ
`fileName` ที่แอปส่งผ่านการทำความสะอาดแล้ว: อักขระ `# % : * ? " < > | / \` และอักขระควบคุมถูกแทนด้วย `_`, ตัดจุดและช่องว่างท้ายชื่อ, ภาษาไทยและช่องว่างกลางชื่อคงเดิม และเป็นชื่อเดียวกับไฟล์ที่เก็บในเครื่อง (ถ้าชื่อซ้ำแต่เนื้อต่างจะเป็น `ชื่อ_1.pdf`)
`contentBase64` คือเนื้อไฟล์เข้ารหัส base64 และ `sha256` คือค่า sha256 (ตัวอักษร hex พิมพ์เล็ก) ของเนื้อไฟล์ก่อนเข้ารหัส
header `X-Api-Key: <คีย์ที่ตกลงกัน>` (ไม่บังคับ แต่แนะนำให้ Flow ตรวจซ้ำ)

คำตอบ HTTP 200 JSON: `{"fileUrl": "https://...", "folderUrl": "https://..."}` หรือ `{"error": "ข้อความ"}`
แอปถือว่าสำเร็จเมื่อ `fileUrl` เป็นลิงก์ http(s) เท่านั้น

สิ่งที่ Flow ควรทำ: ตรวจ `X-Api-Key`, สร้างโฟลเดอร์ซ้อนชั้นตาม `folderParts` (ต้องลองจริงว่าสร้างซ้ำแล้ว error หรือไม่), สร้างไฟล์ (ตรวจ sha256 ได้), ตอบลิงก์, และเปิดการแจ้งเตือนเมื่อ Flow ล้มเหลว

## สัญญาการส่งแถวเข้า Master-List (ข้อเสนอ ใช้เมื่อคำตอบข้อ 6 คือ "ต้องส่ง")

ฝั่งแอปเขียนแล้วและทดสอบกับ Flow ปลอมเท่านั้น (ยังไม่เคยคุยกับ Flow หรือปลายทางจริง) ถ้า IT ต้องการรูปแบบอื่น แก้ฝั่งแอปได้

คำขอ: `POST` JSON ต่อ 1 แถว (ส่งเฉพาะแถวใหม่ ไม่ส่งซ้ำตอนแนบไฟล์เข้าแถวเดิม ไม่มีไฟล์ ไม่มี path ในเครื่อง ไม่มีรหัสแถวภายใน)
```json
{"requestId": "9c1d7e52-2b4a-4f0e-a6d3-5e8b1c7f0a24",
 "record": {"date": "2026-03-19", "vendor": "...", "category": "...", "total_price": 12345.5, "invoice_status": "...",
            "tel": "...", "tax_id": "...", "pr_run_no": "...", "pr_request_date": "2026-03-01", "qt_no": "...",
            "description": "...", "unit_price": 12345.5, "sharepoint_url": "https://..."}}
```
ฟิลด์ที่ไม่มีค่าส่งเป็น `null` `requestId` สร้างใหม่ต่อการส่ง 1 แถว และเท่ากันทุกครั้งที่แอป retry (เฉพาะ HTTP 429/503) ขอให้ Flow จำ `requestId` ที่ทำสำเร็จแล้วและตอบ `{"ok": true}` แทนการสร้างแถวซ้ำ
header `X-Api-Key` (ไม่บังคับ แต่แนะนำ) ใช้ URL และคีย์ **คนละชุดกับ Flow ส่งไฟล์** (`MASTERLIST_API_URL`, `MASTERLIST_API_KEY`) ถือเป็นความลับเหมือนกัน
คำตอบ HTTP 200 JSON: `{"ok": true}` หรือ `{"error": "ข้อความ"}` แอปถือว่าสำเร็จเมื่อ `ok` เป็น `true` เท่านั้น
พฤติกรรมเมื่อล้ม: การบันทึกรายการไม่ล้มตาม (แถวและไฟล์ในเครื่องอยู่ครบ) แอปแจ้งผู้ใช้ว่า Master-List ส่งไม่สำเร็จ รอตอบไม่เกิน 30 วินาที (`MASTERLIST_TIMEOUT_SECONDS`) ไม่ retry เมื่อ timeout, 502/504, การเชื่อมต่อหลุด หรือตอบ 2xx ที่ไม่มี `ok: true` และบอกให้ตรวจ Master-List ก่อนส่งซ้ำ ตอนนี้ยังไม่มีปุ่มส่งแถวนี้ซ้ำ และไม่เก็บสถานะส่งแล้ว/ยังไว้ต่อแถว

## ข้อกำหนดความปลอดภัยและพฤติกรรมของแอป

- URL ของ Flow มีลายเซ็นลับในตัว ถือเป็นรหัสผ่าน เก็บใน `.env` (`POWER_AUTOMATE_UPLOAD_URL`, `chmod 600`) แอปไม่ลง log/หน้าจอ ต้องเป็น `https://`
- แอปไม่ตาม redirect
- retry (สูงสุด 2 ครั้ง) เฉพาะ HTTP 429 และ 503 ซึ่ง Flow ยังไม่ได้เริ่มทำงาน **ไม่ retry** เมื่อ timeout, HTTP 502/504, การเชื่อมต่อหลุดระหว่างส่ง และ 2xx ที่ไม่มี `fileUrl` เพราะ Flow อาจสร้างไฟล์ไปแล้ว (กันไฟล์ซ้ำ) ส่งหลายไฟล์แล้วล้มกลางชุด แอปหยุดส่งไฟล์ที่เหลือและบอกว่าส่งแล้ว/ยังไม่ได้ส่งไฟล์ไหน กรณีเหล่านี้แอปแจ้งผู้ใช้ว่า "ไฟล์อาจถูกสร้างบน SharePoint ไปแล้ว ตรวจในไลบรารีก่อนส่งซ้ำ"
- ค่าตั้ง: `STORAGE_BACKEND=powerautomate`, `POWER_AUTOMATE_API_KEY`, `POWER_AUTOMATE_TIMEOUT_SECONDS` (120), `POWER_AUTOMATE_MAX_FILE_MB` (50)

## วิธีตรวจหลังสร้าง Flow

ขั้นนี้ผู้ดูแลแอปเป็นคนรัน IT ไม่ต้องติดตั้งอะไร เมื่อ IT ส่ง URL และคีย์ของ Flow มาทางช่องทางลับแล้ว ผู้ดูแลแอปตั้งค่าใน `.env` แล้วรันในโฟลเดอร์โปรเจกต์ (ใช้ **ไลบรารีว่าง** ก่อนเสมอ):
```
venv/bin/python scripts/check_flow.py
```
ส่งไฟล์ข้อความเล็ก ๆ (ไม่มีข้อมูลจริง) ไปโฟลเดอร์ `_connection_test` เท่านั้น แล้วพิมพ์ชื่อเซิร์ฟเวอร์ ลิงก์ที่ Flow ตอบ และผลตรวจ ไม่พิมพ์ URL เต็มหรือคีย์ ต้องลบไฟล์ทดสอบเองในไลบรารี
