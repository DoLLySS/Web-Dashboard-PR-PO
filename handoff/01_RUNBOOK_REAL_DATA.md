# คู่มือทำบนข้อมูลจริง

เขียนสำหรับ: หัวหน้า หรือผู้ที่เข้าโฟลเดอร์ข้อมูลจริงได้ (ผู้ช่วยพัฒนาเข้าข้อมูลจริงไม่ได้ จึง **ไม่เคยรันคู่มือนี้กับข้อมูลจริง** ซ้อมกับข้อมูลปลอมแล้ว 21/21)

คำสั่งทั้งหมดเป็นของ `scripts/backup.py` และ `scripts/purge_deleted.py` (รายละเอียดเต็มใน `DEPLOY.md` หัวข้อ 5)

## เลือกเส้นทาง

- **เส้นทาง B (แนะนำก่อน):** ไม่อัปเดตโค้ดจริง คัดลอกเครื่องมือ 5 ไฟล์ไปรันที่โฟลเดอร์อื่น ใช้ Python มาตรฐานของเครื่อง
- **เส้นทาง A:** อัปเดตโค้ดจริงด้วย (ทำหลัง B และมีชุดสำรองโค้ดแล้ว)

## ขั้นตอน (เส้นทาง B)

1. **หาตำแหน่งข้อมูล:** ไฟล์ฐานข้อมูล (ค่า `DB_FILE_PATH` ใน `.env` หรือ `data/masterlist.db`) และโฟลเดอร์ `static/local_uploads` ของโปรเจกต์จริง *อย่าส่งค่าใน `.env` ให้ใคร*
2. **แตกเครื่องมือ** `masterlist_tools.tar.gz` ไว้โฟลเดอร์ใหม่ (ตรวจ checksum ตาม `00_SUMMARY.md` ก่อน) ภายในมี `scripts/backup.py`, `scripts/purge_deleted.py`, `scripts/__init__.py`, `utils/__init__.py`, `utils/file_removal.py`
3. **สำรองข้อมูล** (รันได้ขณะแอปทำงาน):
   ```
   python3 -I -S scripts/backup.py --db <ไฟล์ฐานข้อมูล> --uploads <local_uploads> --dest <ที่เก็บสำรอง>
   ```
   ถ้าจะอัปเดตโค้ดด้วย เพิ่ม `--code <โฟลเดอร์โปรเจกต์>`
   ตรวจ: เข้าโฟลเดอร์ชุดสำรองแล้วรัน `sha256sum -c MANIFEST.sha256` ต้องขึ้น OK ทุกบรรทัด
4. **ดูสรุปก่อน (ไม่เปลี่ยนอะไร):**
   ```
   python3 -I -S scripts/purge_deleted.py --db <ไฟล์ฐานข้อมูล> --uploads <local_uploads>
   ```
   ถ้าสคริปต์บอกว่าไม่พบไฟล์ที่แถวอ้างถึงเลย แปลว่า `--uploads` น่าจะผิด ให้หยุดและตรวจ path
5. **หยุดแอป** แล้วล้างจริง (สำรองให้ก่อนเสมอ ต้องพิมพ์ `PURGE` ยืนยัน):
   ```
   python3 -I -S scripts/purge_deleted.py --db <ไฟล์ฐานข้อมูล> --uploads <local_uploads> --apply --dest <ที่เก็บสำรองก่อนล้าง>
   ```
6. **เปิดแอปและตรวจตาราง** ว่าแถวที่ใช้งานอยู่ครบ
7. **ย้อนกลับถ้าผิดปกติ:** หยุดแอป แล้วคืนจากชุดสำรอง (ตามหัวข้อ "กู้คืน" ใน `DEPLOY.md`)
   ```
   cp <ชุดสำรอง>/masterlist.db <ไฟล์ฐานข้อมูล>
   rm -f <ไฟล์ฐานข้อมูล>-wal <ไฟล์ฐานข้อมูล>-shm
   tar -xzf <ชุดสำรอง>/local_uploads.tar.gz -C <โปรเจกต์>/static
   ```
   (`tar` ไม่ลบไฟล์ที่เพิ่มหลังวันสำรอง ถ้าต้องการให้ตรงทุกไฟล์ ให้ย้าย `static/local_uploads/` เดิมออกก่อน)

## เส้นทาง A (อัปเดตโค้ด) เพิ่มเติม

- ต้องมีชุดสำรองที่ใช้ `--code` ก่อน
- แตก `masterlist_code.tar.gz` (โฟลเดอร์ `masterlist/`) ทับโค้ดเดิม **อย่าให้ทับ `.env`, ฐานข้อมูล, `static/local_uploads`** (ไฟล์ส่งงานไม่มีสิ่งเหล่านี้)
- venv จริงต้องติดตั้ง dependency ตาม `requirements.txt` (**ขั้นนี้ยังไม่เคยทดสอบ**)
- ย้อนโค้ดจากชุดสำรองแล้วไฟล์ที่รุ่นใหม่เพิ่มมาจะค้างอยู่ (ไม่กระทบรุ่นเก่า)

## ข้อควรระวัง

- ชุดสำรองที่ใช้ `--code` มี `.env` (รหัสลับ) เก็บให้ปลอดภัย สคริปต์ตั้งสิทธิ์ให้เจ้าของอ่านคนเดียวและห้ามวางใน `static/`
- ชุดสำรองมีข้อมูลเก่าครบ (รวม Description และ Company)
- สคริปต์ไม่ลบไฟล์บนที่เก็บออนไลน์ และไม่ลบ `data/local_uploads/` รุ่นเก่า (นับให้ในสรุปเท่านั้น)
- ปลายทางสำรองควรอยู่คนละดิสก์กับข้อมูลจริง
